galgame一人制作指南

CloudBase 云开发 AI编程 UniApp 独立开发
项目复盘
发布日期:   2026-11-04

一个人，没买服务器，没买ai api，没写一行后端代码，没配过任何环境。

作为一名喜欢动漫的coser，终于复刻出小时候喜欢的肥宅文字游戏了。

来，先给你们看看上线宣传图（雾）。

这是打开之后第一个页面，选角色。

12个人，男女各6个。冷脸霸总、银发剑客、阳光学长、清冷师尊……往那一排，你自己翻牌。

选完直接进游戏。剧情大概这个画风——

长夜、星辰、宿命、轮回，整一套世界观我给你塞满了。你做每一个选择都不是闹着玩的，羁绊值会变，人格走向会偏，每条分支都真真切切不一样。

玩到最后，AI根据你所有选择给你画一张专属Q版纪念结局图，或成为恋人，或成为朋友

（还在内测中呢）

你跟你选的那个人，被你一路的选择捏成了一对Q版小人。就，挺可爱的。

听起来是不是有点东西？

👉 网页版体验链接：https://newtest-6gzd5kqm6c4eaa2b-1308771514.tcloudbaseapp.com/star/

希望能切成手机屏幕大小（

但说实话，我编程基础真的很浅。

前端就了解了个大概，Vue、TypeScript 知道一点皮毛。后端？数据库？服务器配置？俩月前对我来说跟天书没什么区别。

然后我花了4天，从零到上线，把这个东西做出来了。

怎么做的？

AI 工具 + 腾讯云开发 CloudBase skills。

就这俩。

你可能觉得，AI写代码不是人人都在用吗，有什么好说的？

有道理。

但关键不在这里。

关键是——我把所有后端逻辑、数据库、AI模型调用、部署上线，全都丢给了云平台去管，自己只负责写业务逻辑设计和页面。

什么意思呢？

我没配过Nginx。没装过MySQL。没买过服务器。没搞过域名备案。甚至没管理过API Key。

这些东西全部消失在我的开发流程里。

下面我把整个过程拆开讲讲。

一、遇到了哪些头疼的问题，怎么解决的

先说坑。

做这个项目我碰上的第一个问题：剧情单调。

一开始我写了一条线，12个角色全部走同一套剧本。你知道的，同一个故事，顾沉舟走一遍、陆衍走一遍、白时屿走一遍……越玩越觉得怎么全是那句“长夜将临”、“执灯人的宿命”。

腻了。

然后我就想，那我给每个人写不同的剧本不就行了？

但问题来了——写死一条线太单薄，写多条线又太累。

怎么办？

我就搞了个节点图 + AI 变体机制。

什么意思呢，就是剧本不再是一条线顺序往下走，而是变成一张图。每个节点可以跳到不同的地方。

你选“我跟你并肩作战”→ 跳到节点 s3，看到的是并肩作战的剧情。你选“我觉得冷静一下”→ 跳到节点 s4，看到的就是另一条路的故事。

它不按顺序走，按图走。想说哪个故事就跳到哪个节点，想分支就分支、想汇合就汇合。

而且同一个场景我还塞了几个变体——比如“雨夜街头”，这次可能刷出「他站在路灯下等你」的旁白，下次就变成「雨停了，街上一个人都没有」。同一个地点，每次看到的细节不一样。

这样一来，12个角色写了8套完全不同的主题剧本：商战、青梅竹马、地下乐队、校园暗恋、便利店日常、都市暧昧、职场新丁、归家与亲情。剩下4个保留原来的史诗线。每一套约5个抉择点 + 1道开放题，全篇6~8个关键选择的分支量。

一个JSON就能编一套全新剧本，零代码改动。

再加上AI的不定期台词和结局。

这解决了“重玩一样就腻了”的问题。

第二个坑：AI生成太慢，响应超时。

如果说做成一个纯Agent智能体来完成对话，那跟我去和gpt聊天有什么区别。

我甚至还要去费劲的打字聊天，

可是我只是想看剧情放松，就像读一本小说一样，它有配图，有变动的语录，可以反复看，如同传统的旮旯给木

不想卡在每一幕等待的时间里。

我当时想到的解法就四个字：兜底优先。

具体怎么做呢？

每一处 AI 调用我都在代码里备了一份内置的“兜底版本”：

  • AI 生成台词超时了？→ 用选项里写死的 reply 兜底回复。
  • AI 结局报告没返回？→ 用 endings.report 内置判词顶上。
  • AI 生图失败/超时？→ 直接回退到预设的结局图库。

主流程零中断。AI 成功就锦上添花，AI 失败玩家完全无感。

这是整个项目很重要的工程决策。我不知道其他做 AI 产品的团队怎么想的，但我作为一个玩家，如果游戏卡了30秒告诉我“请重试”，我直接就关了。

我不想我的玩家有这种体验。

第三个坑：云函数容易被白嫖。上线第二天随手 curl 了一下自己的云函数地址，返回了 AI 台词——完了，接口裸奔着。其他人可以把ai接口用作中转站，中间试过在云函数里加身份校验、配安全规则，要么拦了自己人，要么平台端点根本不认规则，踩了一圈寂寞。最后把提示词从搬进云函数（别人看不到模板、也拿不到原始输出），再叠上关网关、配规则、配安全域名，四层压住才算稳。

二、游戏到底怎么设计的

我为啥要自己做一个

galgame、乙女游戏、剧情向手游、RPG大世界网游——这一类我玩了挺多。

玩多了你就会发现一个事：主线永远是编剧写好的，选项再花哨，最后你都被引到“那条唯一被允许走的路”上。

而且大量作品在讨好你。你想要甜就给糖，想要虐就给刀。玩家不是作者，是甲方。

我就想：能不能反过来——

剧情我自己来写，但写完之后让玩家用自己的选择走完它。每个选择真的会改变走向，没有“正确选项”，人格判定也不是分数堆出来的，是玩家在游戏里用行动告诉这个世界“我是什么人”。

它就像一面镜子，照出了我们真实的内心一面

于是就有了这个《辰星 · 长夜轮回》。

世界观

先定调子。

项目里准备了十一种故事，覆盖了大多数人对“一段关系”的想象——

有江湖风雪中的《霜刃寒山》，有校园课本里的《放学后的心跳》，有职场打印机冒烟的《菜鸟修炼手册》，有七年后再见的《那年盛夏》，有暴雨天桥上杀回商场的《凤鸣九天》，有老宅暖房里等着你回家的《归家》，有地下乐队赌上最后一次登台的《追光的我们》，还有便利店关东煮热气里慢慢变甜的日常……

从奇幻到现实，从热血到温柔，每个人都能找到自己想代入的那一个世界。

核心设计：传统文游 + AI 点睛

这个项目的底色还是传统文字游戏的写法——剧情结构、选项分值、流程跳转、配图气氛，这些决定沉浸感的东西，都老老实实地预设好。

AI 呢？放在“变化”的地方，给故事加一点不可预料的鲜活感：

  1. 每次选了选项之后，AI 给你角色回应的台词 + 内心 OS（高频率，6~8次）
  2. 开放题，你用一段话跟角色掏心窝子，AI 用角色的口吻回应你（1次）
  3. 结局报告，给一个总结（1次）
  4. 结局 Q 版纪念图（1次）

说白了，故事骨架和节奏是你精心打磨的，AI 负责在那些“玩家想跟角色多说两句”的时刻，给出有温度的、每次不一样的回应——让传统文游多点新鲜感，而不是让 AI 替你讲故事。

技术架构

眼尖的可能发现了，没有传统后端。

没有 Express，没有 Nginx，没有 MySQL 配置文件。整个项目的「后端」就是一个 AI 代理云函数，加起来不到 100 行代码。角色数据、剧本逻辑、结局图库全部走本地 JSON，不存档、不登录、不记你是谁。

这是故意的。我不存任何用户数据，连 IP 都不落库。隐私合规？零负担。

为什么选 UniApp？ 一句话，一套代码能打四端，微信小程序、H5 网页、iOS/Android App、PC 浏览器，全都能跑。技术细节我也说不上来，反正 UniApp 自动帮你处理了底层差异，写一套 Vue3 就行。

节点图剧本引擎

传统文字游戏怎么做？一条线顺序下去，选 A 走 3，选 B 走 4，if/else 写死。

我没这么干。我设计了一个节点图。

简单说，剧本不再是一条线，而是变成一张图，每个节点可以跳到不同的地方。你选什么，就跳到哪个节点，分支、汇合都能搞定。

这个设计的妙处是，写新剧本几乎不用改代码。一个 JSON 文件描述整张图，换一套剧情就是换一个文件，零代码改动。编剧可以专注写故事，程序员不用动一行代码。

所以这个节点图其实不只 galgame 能用，测试题、心理测评、互动小说，都能套。

结局策略，玩家在剧情里到底是个什么人

剧本是我写的，但最终站在那个位置上的人，是玩家自己。

我一直觉得这事儿挺有意思的。

传统文字游戏怎么判结局？好感度堆到某个数，解锁好结局。低于某个数，坏结局。一条线、一个分、一个人格。线性、一维。

我觉得无聊透了。

你想啊，玩家从头到尾都在做选择，有时候真心的，有时候嘴硬的，有时候撒娇的，有时候冷淡的。人本来就是复杂的，凭什么最后给我一个数字决定结局？

所以我搞了个两级漏斗。

第一级，特殊结局。 判定条件不是「好感度够不够」，而是你有没有形成一种主导人格。你必须在 6~8 个关键选择里，至少 5 次选择同一类。5 次选了「真心」，就锁定了「同行者」结局。5 次选了「渣」，就锁定了「噬星者」结局。

真心 → 同行者
海王 → 逐光者
忠犬 → 拾光者
渣 → 噬星者

为什么设 5 次？因为我想逼玩家亮出底色。你不能「我既要又要」，你得用行动告诉这个世界「我是什么人」。这是有态度的玩家，不是哪儿都讨好的墙头草。

第二级，普通结局。 如果你选得很散，真心 3 次、海王 2 次、忠犬 2 次，那不好意思，你没形成主导人格，特殊结局跟你没关系。这时候回退到羁绊值阈值匹配，按好感度给个普通结局收场。

另外提一嘴，每套剧本的结局 title 都是编剧自己起的，比如「同桌人」「同灶人」「同舟者」「剑侣」「那扇门」这种，跟剧本主题贴得很紧。所以「玩家最终长成的那个人」长什么样，每条线都不一样。

三、我是怎么用 CloudBase 的——实际对话实录

好了，设计和坑都聊完了。说最核心的。

我到底怎么跟 CodeBuddy 说的，让它帮我把 CloudBase 用起来？

这部分是真的“我用自然语言说人话 → AI 帮我搞定所有底层操作”。

第一句：初始化项目

我在 CodeBuddy 对话框里敲的第一句是：

“现在要初始化一个项目，我这个项目要手机移动端的，支持小程序的，同时也能电脑打开的，三端，主要是给微信小程序，然后你要初始化那个模版弄好。要用什么 sdk 你找一下。是不是用 uniapp 还是什么技术栈啊。我不会 flutter 不要。记得用最新的。”

就这一句话。

AI 自动完成了：

  • 判断应该用 UniApp (Vue3) 而不是 Flutter
  • 下载 CloudBase 官方 UniApp 模板
  • 安装依赖并验证微信小程序能编译
  • 创建 START.md 三端启动手册

它选了 @cloudbase/js-sdk + @cloudbase/adapter-uni-app 这两个 SDK，不是我选的。我根本不知道这两个东西的区别。

第二句：配环境变量和数据库

“那你给我新建一个 env，我要填什么东西，环境变量吗，我要用云数据库、云函数、ai 能力，怎么搞啊。”

AI 干了这些：

  • 帮我写 .env.example 模板文件
  • 改造 src/utils/cloudbase.ts 初始化
  • 新建三个工具文件：db.ts（数据库增删改查）、cloudfn.ts（云函数调用）、ai.ts（AI 生成）
  • 创建云函数样例 cloudfunctions/ai-chat/
  • 写了一整篇 CLOUDBASE_SETUP.md 告诉你每一步去哪个控制台链接点哪个按钮

第三句：部署

“这个项目用部署到云开发。”

一句话。AI 自动调用 CloudBase MCP，把前端打包、上传到静态托管、给我一个公网域名。没有 SSH，没有 Nginx 配置文件，没有 CI/CD 脚本。

MCP：在编辑器里用“说人话”操控云

CloudBase 的 MCP 内置在 CodeBuddy 里之后，你的对话就变成了：

你说的话 它做的事
“登录云开发” 弹浏览器授权页
“部署云函数” 自动调 CLI 把云函数推到云端
“部署项目” 打包前端 → 上传静态托管 → 给临时域名
“帮我检查环境配置对不对” 调用 MCP 读环境信息，列出缺失项

你不需要知道 tcb fn deploy 要加什么参数，也不需要知道静态托管的上传路径是什么。说人话就行。

这次最让我省心的，云函数 + CloudBase AI+

我开头不是说嘛，我最愁的就是不想自己买 token、不会管 API Key、不会选模型。

然后我试了下 CloudBase AI+，整个过程就一句话，在云函数里初始化 SDK，一行调 AI。

说真的，看到一行代码就能调大模型那一刻，我是真的愣住了。这玩意我之前折腾了三天没跑通。

那这个 AI 具体在游戏里干了啥呢？四个地方。

每次你选完一个选项，AI 给你角色回应的台词加一句内心 OS。这是最有魅力的设计，AI 给的内心 OS 跟表面台词是有反差的。好感度高就脸红口是心非，好感度低就冷淡疏离，玩起来你会觉得这个角色是真的「活的」。

然后是开放题。你在某个关键节点打一段话跟角色掏心窝子，AI 用角色的口吻回应你。这是整条故事线里唯一一次「你对角色说真话」的机会。

最后是结局报告，根据你这一路的选择，AI 给你写一段恋爱小结，口吻随结局变，甜的时候齁甜，毒舌的时候像损友。

外加一张 Q 版纪念图，把你和角色画成一对 Q 版小人。

文本生图都走同一个 SDK，不用额外集成。说实话这种「所有 AI 能力打包给你」的感觉，是真的爽。

为什么这个项目要走云函数？ 前端把数据丢给云函数，云函数用云端凭证调 AI，结果返回来。这样用户开启匿名登录后，前端完全不碰任何凭证，token 消耗也都在云开发资源包里统一扣，省心又安全。

我之前做了个其他小项目想接 OpenAI，光 API Key 的环境变量管理 + 跨域 + 鉴权报错 + 计费查询这套搞了三天，最后还没跑通。这次云函数里一个文件搞定，幸福感爆棚。

👉 CloudBase AI+ 文档

四、我的感受

做这个项目最大的感受是，开发门槛真的变了。

你想想以前做全栈，买服务器，配环境，装数据库，写后端，配路由，写前端调 API，配 Nginx，部署，折腾半天域名没备案。每一环都能把一个初学者卡死。

现在呢？

服务器不用买了，CloudBase 替你管。数据库不用装，建个集合就能用。后端不用搭框架，写个云函数，几行代码就能暴露 API。AI 不用自己接，SDK 内置，一行调。部署更不用折腾，一句话 MCP 自动完成。

剩下的，真的就是你脑子里的想法、你的设计。

我作为一个初学者，没在环境配置上浪费一分钟。我从第一天起就在写游戏引擎，节点图、剧情故事、人格判定、业力回收，这些真正能让我学到东西、做出差异化的事情。

环境准备，传统方式半天起步，我现在 5 分钟。后端开发，传统方式几天，我现在一个云函数半天。AI 接入，传统方式申请 Key 看文档封装 SDK，我现在 SDK 内置直接调。部署上线，传统方式 CI/CD 折腾，我现在一句话搞定。算下来，传统方式以周为单位，我总共 4 天，其中大部分时间是在策划、切图、美术、优化剧情。

还有一点，边界感很重要。

AI 只做四处，别的是我自己写死的。

为什么？我知道 AI 什么时候靠谱，什么时候不靠谱。剧情结构、选项逻辑——错了体验直接崩。AI 放到“画龙点睛”的位置，不是“替代你思考”。

一天构思剧情文案世界观策划，一天搞美术素材切图，半天处理技术架构，半天使用工具辅助项目成型，一天测试。

这对于不懂技术的人来说，实在是太方便了。
